## 后续交接顺序

1. 评审本轮基线，检查正式活动和成员聚会是否各有完整可用路径。
2. 进入实际UI前确定改动位置和范围；未经明确阶段授权，不直接改原站或启动后端。
3. 实际UI按组件规格制作真实视觉页面，使用明确标注的演示资料；不混淆展示与真实服务。
4. 后端实施前专项确定账号、组织初始化、年龄与必要资料、保存注销策略、通知渠道、部署与维护责任，再完成技术方案、接口契约及权限测试设计。
5. 免费闭环以PRD G01–G14逐项验收；公开测试前完成素材及真实学校资料核验。收费、段位榜、文件托管另立专项，不隐式加入首发。

当前无需用户提供真实学生名单、游戏账号、学校精确位置或支付资料。后续问题在对应阶段提出，避免设计期过早采集。
